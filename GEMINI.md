# gpu/lab — Gemini & Antigravity Agent Guide

`gpu/lab` is our collective's **zero-abstraction, first-principles** open-source AI engineering study book and lab. It starts from basic Python fluency and reasons bottom-up — through matrices, GPU hardware physics, a 40-line autograd engine, and a 120-line toy Transformer — all the way to **Gemma 4** fine-tuning and serving (Capstone 1), **voice cloning** and **<800 ms live phone agents** (Capstone 2), and **native full-duplex speech-to-speech**.

Write for **the collective** (address the reader directly as "you"; never hardcode an individual's name). Every chapter, exercise, and lab should feel like one cohesive book — clear enough for self-study with zero prior ML, PyTorch, calculus, or audio background, and rigorous enough for production systems engineers.

## Optimized Learning Environment (Read First)

This repository is engineered for **two first-class reading & coding modes**:

1. **Antigravity IDE Study Cockpit (`make study`) — primary daily workflow:**
   - **Left pane (Simple Browser → `http://127.0.0.1:8000`):** Full visual HTML book + on-the-fly book-styled Markdown (`gpu-labs/`, `journal/`), scroll-preserving live reload when chapters are edited, 1-click **Open `.py` / Open tests / Debug :L&lt;line&gt;** via `antigravity-ide`, auto-`pytest` on save with local-variable tracebacks, 1-click **Copy trace prompt** for failing tests, and a sticky **Last saved exercise** bar across cheatsheets & chapters.
   - **Center pane (`exercises/` + `.vscode/`):** Real `.py` files with `"debug.inlineValues": "on"` and `F5` loop-by-loop stepping (`justMyCode: true`).
   - **Right pane (Antigravity Chat):** Loop-by-loop Socratic debugging (`trace-and-debug`) and live in-place chapter explanations/extensions (`study-and-extend`).
2. **100% Offline HTML & GitHub Pages (`book/`):** Every HTML page under `book/` works standalone over `file://` and on GitHub Pages with zero external network calls or `fetch()`.

**Compute & Branch Discipline:**
- **Local CPU first:** Phase 0A, Phase 0B, and Stage 1 run 100% locally on CPU (`pytest` + NumPy). Remote GPU execution (**RunPod pods** and **SSH GPU VMs**) is deferred until Stage 2+ (`gpu-labs/` + `run-gpu-lab` skill).
- **`main` stays clean (stubs only):** Never commit solved exercises to `main` (verified by `make check-main` and CI). Personal solved exercises and study progress live on a dedicated branch (e.g., `study/my-work`), while book/tool improvements live cleanly in `book/` and `tools/`.

## First-Principles Philosophy (Non-Negotiable)

Assume **only basic Python fluency**. Never treat a framework call (`nn.Linear`, `SFTTrainer`, `vLLM`, `Mimi`, `Pipecat`) as a black box until the reader has traced or built the tiny toy version underneath it:

1. **Pain + payoff first:** Open with a concrete hardware wall, OOM crash, latency stall, or naive failure with small numbers — never a textbook definition.
2. **One running physical anchor:** Carry one concrete physical or geometric analogy across the entire rebuild, and state explicitly **where the analogy breaks**.
3. **Bottom-up derivation ladder:** `Concrete Pain → Naive Attempt → Break → Hand-Traced Toy Numbers (2–4 elements) → Visual Model → Plain English → Formal Name & Equation → Pure-Python/NumPy Build (≤15 lines) → 1-to-1 Bridge to Real Stack & Gotchas`.
4. **Protect the core path:** Keep chapters to ~2,000–3,500 visible words, place the first visual in Section 1–2, leave at most 2 consecutive sections without a visual, and tuck heavy derivations or secondary variants into collapsed `details.aside.deeper`.
5. **Test causal prediction, never trivia:** Quick checks and quizzes ask "what breaks if we double X while holding Y fixed?", never acronym memorization. When teaching or quizzing interactively, pace one step or question per turn and stay inside the topic's `curriculum.json` `requires`.

## Hard Rules (Never Violate)

1. **Never write or commit exercise solutions on `main` or in chat** (including drop-in formulas). Exercise stubs in `exercises/<NN>-<slug>/*.py` on `main` must raise `NotImplementedError` in every function/method (verified by `make check-main`). When helping a learner debug an exercise, activate `trace-and-debug`: run `pytest` first and give one progressive loop-tracing hint per turn rather than the answer. Verify new test suites via `tools/check_exercise.py` using temporary files *outside* the repo, then delete those scratch files.
2. **Never add external web dependencies to `book/` HTML pages:** Zero CDNs, zero external fonts/scripts, zero `fetch()`. Every page in `book/` must work completely offline over `file://` using `assets/style.css`, `assets/viz.js`, `assets/shell.js`, and `assets/book.js`. (Cockpit scripts are injected dynamically only by `tools/study.py` over `127.0.0.1`.)
3. **Never hardcode colors in HTML/SVG/CSS/JS:** Use only CSS theme tokens (`var(--accent)`, `--accent-2`, `--brand`, `--ok`, `--warn`, `--bad`, `--surface`, `--surface-2`, `--border`, `--text`, `--text-strong`, `--muted`, `--on-accent`, `--*-soft`) so all four themes (Ayu Dark, Ayu Mirage, Gruvbox Dark Hard, Ayu Light) stay legible.
4. **Never leak Markdown or unescaped special tokens into HTML:** Use `<code>...</code>` (never raw `` `backticks` ``), `<b>`/`<em>` (never `**bold**`), and escape angle-bracket tokens (`&lt;|turn&gt;`, `&lt;turn|&gt;`).
5. **Never eyeball ML/hardware math or guess framework APIs:** Run `python3` to verify every FLOP count, byte count, VRAM sum, tensor shape, and latency budget. Cross-check Gemma 4 and voice stack specs against `book/reference-cheatsheet.html` or official docs before stating them.
6. **Never break prerequisite order or skip `tools/build.py`:** Never lean on concepts introduced later in `curriculum.json`. Every topic's `requires` list must stay strictly monotonic; run `python3 tools/build.py` after adding, renaming, or completing any chapter or exercise, and commit the regenerated `book/assets/curriculum.js`.
7. **Keep `"gpu-lab:"` localStorage isolation and unique exercise module names:** Every HTML page uses `"gpu-lab:theme"` in its inline theme script. Never add `__init__.py` inside `exercises/`; every exercise module name must be unique repo-wide.
8. **Never use patronizing filler prose:** Ban "simply", "obviously", "just", "trivially", "easily", "delve into", and "unlock the power of".
9. **Always verify before finishing:** Run `python3 tools/check_chapter.py` + `python3 tools/build.py` (and `node tools/check_page.js` when Playwright is installed) on chapters, `make check-main` before committing to `main`, and `tools/check_exercise.py` on new exercises.

## Agent Skills (`.agents/skills/`)

Activate the matching skill before starting work — keep procedural detail in skills, not in ad-hoc improvisation:

| Task | Skill / Pipeline |
|---|---|
| Debug a failing CPU exercise loop-by-loop with breakpoints & Socratic hints | `trace-and-debug` |
| Explain a chapter section or safely extend a chapter live in Antigravity IDE | `study-and-extend` |
| Run a cloud GPU lab on RunPod or SSH VMs (Stage 2+, pre-flight + teardown) | `run-gpu-lab` |
| Write or rewrite a visual HTML book chapter (`book/sections/*/concepts/*.html`) | `write-chapter` → `visuals-and-layout` → `review-chapter` |
| Design or polish SVG diagrams, `book/assets/viz.js` widgets, themes, and mobile layout | `visuals-and-layout` |
| Adversarially review an existing chapter for math, clarity, gotchas, and markup | `review-chapter` |
| Author a new zero-GPU pure-Python/NumPy exercise + adversarial `pytest` suite | `author-exercise` |
| Write or update a reproducible cloud GPU lab runbook (`gpu-labs/<NN>-<slug>/README.md`) | `write-lab` |

## Commands

```bash
make study                                                # launch Antigravity IDE Study Cockpit (http://127.0.0.1:8000)
make check-main                                           # verify every exercise stub raises NotImplementedError on main
python3 tools/new.py concept 01.01 slug "Title"           # scaffold: concept | exercise | eval | exp | runbook | capstone
python3 tools/check_chapter.py <page.html>                # zero-dependency HTML, offline, theme-token & pacing linter
python3 tools/check_chapter.py --all                      # lint all completed chapters in book/sections/
python3 tools/build.py                                    # validate prerequisite DAG & regenerate book/assets/curriculum.js
python3 tools/check_exercise.py <mod> --pass /tmp/ref.py --fail /tmp/bad.py
python3 -m pytest -k <mod>                                # run one local CPU exercise
node tools/check_page.js <page.html> [--shots DIR]        # headless browser layout & 4-theme check (requires Playwright)
```
